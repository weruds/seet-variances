1 What This Dashboard Does

The ODC SEET Variance Dashboard (myMVP) is a browser-based tool for monitoring, validating, and pinpointing attendance variances within the ODC SEET team. It compares two attendance data sources — Monday.com records and ILC (IBM Labour Centre) clockings — against employee WFH schedules, surfaces discrepancies, and allows employees to submit explanations for review by auditors.

4 Accessing the Dashboard

Option A — Use the hosted site (recommended)

Open any modern browser (Chrome, Edge, Firefox) and navigate to:

https://seet-variances.web.app

No installation is needed. Sign in with the IBM email and temporary password provided by your administrator.

Option B — Open the file locally

If you have the project folder on your computer, open index.html directly:

Start-Process ".\index.html"
Local file access may limit Firebase Auth and Firestore functionality due to browser security restrictions. Use the hosted URL whenever possible.

5 First-Time Sign-In Guide

What you need before you start

  • Your IBM email address (e.g. firstname.lastname@ibm.com)
  • A temporary password provided by your administrator
  • A modern browser — Chrome, Edge, or Firefox
  • Internet access

Steps

  1. Open the dashboard. Go to https://seet-variances.web.app in your browser.
  2. Click "Sign in" at the bottom-left of the sidebar.
  3. Enter your credentials. Type your IBM email address and temporary password, then click Sign In.
  4. Set a new password (first login only). The dashboard will prompt you to change your temporary password. Enter a new password (minimum 8 characters), confirm it, and click Update Password.
  5. You are now signed in. The sidebar updates to show the pages available for your role.
After the first login your credentials are saved by Firebase Auth. You will only need to enter them again if you sign out or clear your browser data.

6 Navigation Guide — Step by Step

Landing page

Every user lands on My Variances when they open the dashboard. The left sidebar shows only the sections permitted by your role. The sidebar also displays the current date, quarter, and the Firebase connection status dot at the bottom.

For Employees — View your variances

  1. The default page is My Variances. If you are signed in, your report loads automatically.
  2. If the page shows "Sign in to view your private variance report", click Sign in in the sidebar and follow Section 5.
  3. Use the Refresh button to reload the latest data at any time.

For Admins — Full workflow

A. Set up the employee masterlist

  1. Go to Admin → Monthly Attendance (ILC) and upload an ILC export. The masterlist is auto-populated from ILC uploads.
  2. Alternatively, go to Admin → Onboard New Employee and click ＋ Onboard Employee to add employees manually.

B. Configure WFH schedules

  1. Go to Admin → WFH Schedule.
  2. Click 📤 Upload WFH Schedule and select a CSV or XLSX file.
  3. Use the search box to find a specific employee and edit their WFH days as needed.

C. Upload attendance data

  1. Go to Attendance → Monthly Attendance (ILC).
  2. Click 📤 Upload Monthly Attendance (ILC) and select the ILC export file.
  3. Review the column mapping preview, then click Upload to confirm.
  4. Repeat for Attendance → Monthly Attendance (Monday.com) using the Monday.com export file.

D. Detect variances

Monday vs WFH Schedule:

  1. Go to Discrepancy List → Detect Variances → Monday vs WFH Schedule.
  2. Select the Year and Month from the toolbar filters.
  3. Click 🔍 Detect Variances.
  4. Review the results. Each row shows the employee, their WFH days, the flagged date, Monday status, and the variance type.
  5. Tag individual rows or use TAG ALL to select records for notification.
  6. Click 📧 Notify Employees to send notifications to selected employees.

Monday vs ILC:

  1. Go to Discrepancy List → Detect Variances → Monday vs ILC.
  2. Select Year and Month.
  3. Click 🔍 Detect Variances.
  4. Review discrepancies between ILC clockings and Monday.com records. Tag and notify as needed.

E. Review the discrepancy list

  1. Navigate to Discrepancy List in the sidebar (under the Discrepancy List section).
  2. Filter by Year, Month, Name, or IBM Serial No.
  3. Use the Search box to find a specific employee.

F. Review variance submissions

  1. Go to Variance Review (visible after sign-in for Auditors and Admins).
  2. Open each pending submission to read the employee's explanation.
  3. Approve or reject the submission.

G. Manage roles

  1. Go to Admin → Role Maintenance.
  2. Click ＋ Add User.
  3. Select the employee, assign the role (Admin or Auditor), and click Save.
  4. The new role takes effect on the employee's next sign-in.

10 Deploying Updates

This section is for developers or admins who need to push code changes to the hosted site.

Requirements

  • Node.js 20 or newer (only needed for the Firebase CLI)
  • Firebase CLI installed and authenticated
  • Access to the seet-variances Firebase project

Install Firebase CLI (one-time)

npm install -g firebase-tools
firebase --version

Deploy to production

From the project root folder:

firebase login
firebase use seet-variances
firebase deploy --only hosting,firestore
The hosted site at https://seet-variances.web.app is updated immediately after deploy completes.

Automated deployment (GitHub Actions)

Pushing to the main branch triggers the workflow in .github/workflows/. This deploys automatically provided the Firebase service-account secret is configured in the repository settings.

11 Troubleshooting

Cannot sign in

  • Confirm your email and password are exactly as provided — passwords are case-sensitive.
  • If you forgot your password, ask the administrator to reset it in Firebase Console.

"Connecting…" never changes in the sidebar

  • Check your internet connection.
  • Verify you are loading from https://seet-variances.web.app or a local HTTP server.
  • Open browser DevTools (F12) → Console for Firebase error messages.

I can sign in but see no data

  • Confirm your role has been assigned by an admin in Role Maintenance.
  • Sign out and sign back in — role changes take effect on the next sign-in.

Upload fails or shows no rows

  • Check that the file format is CSV or XLSX.
  • Confirm column headers match the expected names (see Section 8).
  • Large files (> 5,000 rows) may take several seconds to parse.

"Detect Variances" finds nothing

  • Confirm both attendance sources (ILC and Monday.com) have been uploaded for the selected month.
  • Check the Year and Month filters are set correctly.

Firebase deployment fails

firebase use
firebase projects:list
firebase deploy --only hosting,firestore --debug

Confirm you are logged in as an account with access to seet-variances and that firebase.json is present in the project root.

12 Security Notes

  • Do not share your dashboard password with anyone.
  • The Firebase configuration visible in index.html is the public client config — it is intentionally visible but Firestore rules must remain restrictive.
  • Firestore security rules are deployed via firestore.rules. Review them before any broader rollout.
  • Never commit .env files or service-account JSON files to the repository.
  • If credentials are accidentally exposed, rotate them immediately in Firebase Console.
